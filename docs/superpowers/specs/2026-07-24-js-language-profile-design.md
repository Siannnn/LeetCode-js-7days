# 00-配置 目录 JavaScript 学习语境统一设计

- 日期：2026-07-24
- 范围：`00-配置/`
- 主题：将学员档案及相关配置中的 Python 导向表述统一改写为 JavaScript 导向表述

## 1. 背景

当前 `00-配置` 目录中的核心配置，尤其是 `00-配置/学员档案.md`，已经明确了“刷题语言为 JavaScript”“所有代码优先使用 JavaScript”等约束，但仍残留少量 Python 导向表述，例如：

- `Python 熟练度：不太熟，只作为参考`
- `遇到 Python 代码时，请转换成 JavaScript，并解释 JS 写法`
- `能够用 Python 标准库（collections、heapq、bisect 等）熟练解题`

这些表述与当前学员画像不完全一致，可能导致后续 AI 在讲解语言、代码输出语言和学习目标判断上出现混乱。

## 2. 目标

本次改写的目标是：

1. 将 `00-配置` 目录内与语言偏好相关的 Python/py 语境统一调整为 JavaScript 语境。
2. 让后续 AI 在读取配置时，默认以 JavaScript 作为：
   - 刷题语言
   - 题解输出语言
   - 讲解语言与分析视角
3. 保持现有模板结构和风格稳定，不进行无关重构。

## 3. 范围

### 包含范围

- `00-配置/学员档案.md`：主要修改对象
- `00-配置/学习日志.md`：如存在语言导向冲突则做最小修正
- `00-配置/进度看板.md`：如存在语言导向冲突则做最小修正
- `00-配置/全局索引.md`：如存在语言导向冲突则做最小修正

### 不包含范围

- `02-Wiki/` 中的题解与专题总结
- `03-学习笔记/` 中的每日笔记
- 非语言偏好相关的内容结构调整
- 与本次目标无关的字段重构

## 4. 方案选择

### 备选方案

#### 方案 A：最小必要替换
仅替换明确的 Python 字样，不做整体语言画像统一。

#### 方案 B：统一成 JavaScript 学员画像（采用）
在 `00-配置` 范围内，围绕语言偏好、题解输出和学习目标，对相关表述做统一的 JavaScript 化改写，但不重构文档结构。

#### 方案 C：目录级补充语言规范
除替换外，再为日志、看板等模板新增语言规范字段。

### 采用理由

选择方案 B，因为它能够：

- 完成目录范围内的一致性修正
- 明确后续 AI 的默认输出行为
- 避免把本次工作扩大成模板重设计
- 保持用户现有文档风格和使用习惯

## 5. 具体改写策略

### 5.1 直接替换 Python 导向表述

对明显的 Python 目标或能力描述，改写为更贴合 JavaScript 学习场景的内容。

示例方向：

- `Python 熟练度：不太熟，只作为参考`
  - 改为 JavaScript/TypeScript 基础相关描述，强调 JavaScript 是主刷题语言。
- `遇到 Python 代码时，请转换成 JavaScript，并解释 JS 写法`
  - 改为默认使用 JavaScript 讲解；若参考资料来自其他语言，则先转换为 JavaScript 再解释。
- `能够用 Python 标准库（collections、heapq、bisect 等）熟练解题`
  - 改为能够熟练使用 JavaScript 常见解题工具与模板，例如 Array、Map、Set、栈/队列模拟、二分模板等。

### 5.2 统一成 JS 学员画像

在不改变整体结构的前提下，让相关字段形成一致表达：

- 默认输出代码语言为 JavaScript
- 默认题解与讲解语言为 JavaScript
- 外部资料若非 JavaScript，需要转换后再用于讲解
- 学习目标围绕“用 JavaScript 独立完成 Hot 100 常见题型”展开

### 5.3 保留原结构与样式

本次改写不调整：

- 标题层级
- 表格结构
- 清单结构
- 文档整体布局

只对语言导向相关句子做必要替换或轻度润色。

## 6. 执行步骤

1. 检索 `00-配置/` 下所有 Python/py 相关表述。
2. 识别其中属于“语言偏好”“学习目标”“题解输出要求”的条目。
3. 优先修改 `00-配置/学员档案.md`。
4. 对其他命中文件仅在确有语言导向冲突时做最小修改。
5. 修改后再次检索，确认目录内不再残留与本次目标冲突的 Python 导向表述。

## 7. 验证方式

### 文本验证

对 `00-配置/` 目录重新检索以下关键词：

- `Python`
- `py`
- 典型 Python 标准库能力表述（如 `collections`、`heapq`、`bisect`）

确认不再残留与学习语言设定冲突的描述。

### 语义验证

确认改写后的内容能够稳定表达：

- 学员主刷题语言是 JavaScript
- 题解默认输出语言是 JavaScript
- 讲解优先采用 JavaScript 视角
- 学习目标不再以 Python 标准库能力为默认衡量项

## 8. 成功标准

完成后应满足：

1. `00-配置/` 中语言偏好表述前后一致。
2. `00-配置/学员档案.md` 能清楚约束后续 AI 默认使用 JavaScript 进行讲解与输出。
3. 原有模板结构与阅读体验基本不变。
4. 修改范围控制在本次目标内，不扩散到其他学习内容目录。

## 9. 风险与控制

### 风险

- 误把无关字符串当作需要改写的 Python 语境
- 为了统一而过度改写模板
- 将工作范围扩大到知识内容本身，而非配置层

### 控制措施

- 只处理 `00-配置/` 范围
- 只处理语言偏好、题解要求、学习目标相关内容
- 仅在发现明确冲突时修改其他配置文件
- 修改后再次检索验证
