# 13 · 复杂度速查表（JS/TS）

> **核心价值：** 快速判断 JavaScript 数据结构操作是否适合当前题目规模。

---

## 一、常用结构复杂度

| 结构 | 操作 | 平均复杂度 | 备注 |
|------|------|------------|------|
| `Array` | `push` / `pop` | O(1) 均摊 | 适合栈 |
| `Array` | `shift` / `unshift` | O(n) | 不适合大队列 |
| `Array` | 按下标访问 | O(1) | `arr[i]` |
| `Array` | `sort((a,b)=>a-b)` | O(n log n) | 数字排序必须写比较函数 |
| `Map` | `get` / `set` / `has` | O(1) 均摊 | 适合哈希表 |
| `Set` | `add` / `has` / `delete` | O(1) 均摊 | 适合去重/存在性 |
| 自定义堆 | `push` / `pop` | O(log n) | JS 无内置堆 |

---

## 二、常见规模判断

| n 范围 | 可接受复杂度 |
|--------|--------------|
| n ≤ 20 | 回溯 / 状压 / 指数级可能可行 |
| n ≤ 10^3 | O(n²) 可能可行 |
| n ≤ 10^5 | O(n log n) 或 O(n) |
| n ≥ 10^6 | 优先 O(n) / O(1) 额外空间 |

---

## 三、JS 常见坑

1. 大队列不要 `shift()`，用 `head` 指针：`const node = queue[head++]`。
2. 二维数组不要共享行：`Array.from({ length: m }, () => Array(n).fill(0))`。
3. `Map.get(key)` 返回 `undefined` 时要用 `??` 兜底。
4. `Math.max(...arr)` 对很大数组可能栈溢出，用循环更稳。
5. JS 数字是双精度浮点；普通 LeetCode 整数题通常安全，超大整数要考虑 `BigInt`。
